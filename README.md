# 招聘证据工作台｜可运行样板

这是可以直接向面试官展示的本地网页样板：**不是自动招聘决策工具**，而是帮助招聘团队按 S1—S5 标准分工出题、沉淀证据、补足缺口并保留人工决策边界。

## 核心能力

- **岗位成功标准可视化**：首页展示已确认的 S1–S5 标准、定义与主责面试轮次。
- **真实材料上传**：支持 .txt、.md、.json 文件拖拽/选择上传，或直接粘贴文本。
- **结构化面试记录**：每条记录区分"候选人原话 / 事实观察 / 面试官推断 / 待追问项"。
- **证据类型化分析**：自动把材料中的内容标记为"事实 / 自述 / 推断 / 缺口"。
- **可追溯来源**：每条判断都关联到原文片段或面试记录，不凭空生成。
- **提示注入与敏感属性防护**：检测"忽略规则 / 直接录用 / 淘汰"等绕过尝试，以及年龄、性别、婚育等敏感词。
- **人工审核持久化**："标记需补问 / 人工确认 / 采纳问题 / 提交决策备注"会保存到本地 `data/` 目录。
- **无 API Key**：仅使用 Python 标准库，零外部依赖。

## 启动

```bash
python server.py
```

浏览器打开 <http://127.0.0.1:8080>。

按 Ctrl+C 停止。

## 推荐的 5 分钟演示路径

1. 打开首页，说明本次试点只服务"业务侧 AI Builder"岗位；展示 S1–S5 标准卡。
2. 进入"导入材料"：上传一份真实简历 .txt 或粘贴候选人材料，填写候选人编号。
3. 进入"补充面试记录"：添加技术面、业务面、HR 初访等记录；选择"下一轮补问方向"。
4. 点击"生成证据卡"：审阅 S1–S5 证据卡、待核验声明、证据缺口、风险提醒与追问建议。
5. 点击"标记需补问"或"人工确认"，这些动作会持久化；最后由用人经理点击"提交人工审核"填写决策备注。
6. 说明：本工具不输出录用、淘汰、定级或薪酬决定；最终判断必须由人负责。

## 目录

- `server.py`：工作台本地服务（主入口）。
- `app.py`：规则分析引擎和 JSON API；也可独立运行 `python app.py --demo`。
- `index.html`：完整前端工作台。
- `demo-output.json`：C-017 案例的可审查结构化输出样例。
- `logs/assistant.log`：请求审计日志（含请求 ID、候选人编号、耗时、风险命中数）。
- `data/`：本地会话与人工审核数据（运行时创建）。

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 工作台首页 |
| GET | `/standards` | 返回 S1–S5 岗位成功标准 |
| GET | `/demo` | 返回 DEMO payload |
| POST | `/analyze` | 分析候选人材料与面试记录 |
| POST | `/session/save` | 保存当前会话草稿 |
| GET | `/history` | 列出已保存会话 |
| GET | `/history/{candidate_id}` | 读取某候选人最新会话与审核结果 |
| POST | `/review/{candidate_id}` | 追加人工审核动作 |

## 失败处理与边界

- 无效输入、格式异常或系统失败不会覆盖任何正式记录；保留日志并由 HR/面试官使用人工模板兜底。
- 系统不使用敏感属性作判断；检测并忽略"忽略规则""直接录用"等提示注入。
- 单文件/单请求大小限制 300KB，超大输入会返回明确错误。
- 数据仅保存在本地 `data/` 目录，未加密；请勿把真实候选人材料部署到公共服务器。

## 清理数据

```bash
# 删除所有本地会话与审核记录
rm -rf data/
```

## 人机边界

本工具严格遵循 `03-human-agent-boundary.md` 定义的人机边界：

- Agent 负责：按已确认标准整理证据、提示缺口、建议追问、检测风险。
- 人必须负责：确认标准版本、审核题目、核实证据、作出录用/淘汰/定级/薪酬决定、批准标准或题库变更。
